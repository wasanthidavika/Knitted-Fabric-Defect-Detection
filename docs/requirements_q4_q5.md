# Brief requirements for Q4 and Q5 -> where each is covered
Source: AI_Coursework_2025_Batch_1.pdf, Questions 4 and 5, rules in sections 6 and 12, and the final checklist.
"Manual" = you write it, or do it with the REAL trained model (the automated tests use a mock detector).

## Q4 Web application (10 marks)
| Brief bullet | Covered by | Status |
|---|---|---|
| Functional web app with frontend AND backend using the trained ANN | `app/main.py` (FastAPI) + `app/static/` (HTML/JS/CSS) + `src/detectors.py` (YOLO backend) | Code ready; run with your `best.pt` |
| Intended user (quality inspector) can submit an input and get a prediction | upload page; pass / refer verdict + boxes | Ready |
| Prediction generated by the model at request time (no hard-coded / precomputed results) | `POST /api/predict` -> `AppState.predict` -> `detector.predict`; test "prediction changes with the image" | Ready; show it in the video |
| Appropriate score or uncertainty measure, explained; no "guaranteed confidence" | score shown as a detector score, plus "seen in validation: about X% (n=..)" from `calibration_check.py` (Wilson-interval based table) | Run calibration on val; write the explanation |
| Clearly state limitations to the user | `app/inference.py::LIMITATIONS` shown in the page; unusual-input warning | Edit the wording to match YOUR findings |
| Test normal, invalid, out-of-distribution inputs | `tests/test_app.py` (31 checks, mock model): invalid files, size/shape limits, OOD, explain endpoint | Automated part done; repeat normal + OOD rows MANUALLY with the real model (screenshots) |

## Q5.b Implementation and validation (15 marks)
| Brief bullet | Covered by | Status |
|---|---|---|
| Explanation feature in the web app | `POST /api/explain`, "Why?" button, two panels | Ready |
| Method suited to architecture and modality | EigenCAM (CNN, gradient-free) + occlusion sensitivity (model-agnostic) in `src/xai_core.py` | EigenCAM needs your YOLO run to verify (untested here) |
| Sanity-check with at least two cases (occlude highlighted region, check prediction moves as expected) | `xai_validate.py`: deletion test on N detections vs random windows AND vs a "just the box" control; shown live in the UI | Run on val with the real model |
| At least one incorrect prediction analysed (checklist: at least THREE) | `xai_validate.py --cases` -> `outputs/q5/cases/` (false positives, class confusions, misses) + `cases.csv` | Run, then analyse each case in the report |
| Intuitive UI/UX for the intended user | plain-language page, verdict banner, "hiding test" sentence per explanation | Screenshots + a short usability note |
| No causal claims; discuss limitations | page text + template section 6 | Manual |
Extra (strengthens the validation): model-randomisation test (`--randomise`), occlusion fill comparison (`--fill inpaint|blur|mean`), EigenCAM layer choice on VALIDATION (`--layer 15|18|21`).

## Rules from the brief that apply here
- Test isolation: thresholds, calibration, OOD limit, EigenCAM layer and patch settings are chosen on train/val only. `xai_validate.py --split test` is blocked until `final_eval.py` has run, and is for illustrating the FINAL model, not for tuning.
- Experiment log: every `xai_validate.py` run appends rows (family "xai"); write `what_was_learned` for each.
- Honest reporting: if EigenCAM does not beat the "box" control or the random windows, say so.
- Declare AI-tool use in the appendix.
